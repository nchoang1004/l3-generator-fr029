  1. Chỉ đọc code. Không chạy, không import, không sửa repo đầu vào.
  2. Phase đầu chỉ cam kết Python/FastAPI.
  3. Kết luận nào cũng phải có bằng chứng là dòng code có thật, và bằng chứng do code kiểm, không dựa vào lời AI.

  5. AI chỉ dùng gói miễn phí (Groq, Gemini). Trần chi phí 0 đồng.

B · Phần L3 chạy thế nào

Sáu bước của một lần chạy

Gửi một repo là một lần chạy. Phần L3 không dùng AI ở bước nào, nên chạy lại cho kết quả giống hệt.

  1. 1Nhận fileMở ZIP trong bộ nhớ, chặn file nguy hiểm, lấy mã hash từng file
  2. 2Chọn fileGiữ file Python và file khai thư viện, ghi file bỏ kèm lý do
  3. 3Đọc codeĐọc cấu trúc từng file, tìm API, bảng, cấu hình…
  4. 4 · KhiêmChia khốiGom file thành khối. Demo L3 chia tạm
  5. 5Tự kiểmSo từng thông tin với đúng dòng code
  6. 6Viết tài liệuViết file, đọc lại để chắc ghi đúng

Mã hash: chuỗi ký tự tính từ nội dung file. File đổi một chữ thì mã đổi. Công cụ dùng nó để biết file có bị sửa sau khi đọc không. Code ở D:\VSF\l3-generator-l3\slice\l3slice\: snapshot.py (bước 1–2), pyindex.py và extract.py (bước 3), verify.py (bước 5), render.py (bước 6), engine.py và web.py (điều phối, web).

Kiểm thế nào và chắc chắn đến đâu

Ba phép kiểm cho mỗi giá trị (bước 5)

  1. File đúng là file đã nhận, chưa bị đổi (so mã hash).
  2. Số dòng có thật trong file.
  3. Giá trị nằm nguyên văn ở các dòng đó. Đường dẫn ghép nhiều mảnh thì từng mảnh phải có.

Sai một phép thì giá trị bị xóa, ô chuyển sang "chưa biết" kèm lý do. Trên web, bấm nút file:dòng là thấy đúng đoạn code; file đã bị sửa thì web báo, không hiện code mới.
